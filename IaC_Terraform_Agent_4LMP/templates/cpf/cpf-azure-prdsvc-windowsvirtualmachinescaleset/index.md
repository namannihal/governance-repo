# Windows Virtual Machine Scale Set module

## Overview

This terraform module creates a Windows Virtual Machine Scale Set module and associated resources.

## Prerequisites

- `Resource Group`, `Virtual Network`, and `Route Table` (all three modules to be called if not existing).
- `Subnet` to be used by the Private endpoint and the VM Network Interface IP Configs.
- `Network Security Group` to be associated with the Subnet.
- `Keyvault` module to create a secret.
- `Privateendpoint` module to create a private connection to the Keyvault.
- `Role assignment` module to assign "Key Vault Secrets User" role to the client on the created keyvault.
- `Keyvault Secret` module to store the Password for Windows VMSS.
- Optional modules and resources:
  - `User Assigned Identity` and `Proximity Placement Group` modules,
  - `time_sleep` resource block to wait for the secret to get created till private connection is registered in the Private DNS Zone and `random_password` resource block to generate admin_password for Windows VMSS.

## Guidance

#### Usage

AzureRM 4.x Upgrade Notes for Windows Virtual Machine Scale Set.

Impact analysis -- Low

There is no impact for users of this module when migrating from azurerm 3.x to 4.x, as the module already uses the latest arguments as per the 4.x documentation.

Wiki link for [AzureRM 4.x Upgrade](https://gitlab.dx1.lseg.com/groups/app/app-51310/azure/prdsvc/terraform/-/wikis/Terraform-AzureRM-Provider-Upgrade:-Version-3.x-to-4.x/Windows-Virtual-Machine-Scale-Set) for details on the upgrade process.

For more details, refer to the official [AzureRM 4.x Upgrade Guide](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/guides/4.0-upgrade-guide)

- If multiple `network_interface` blocks are specified, one must be set to primary.
- We are using `proximity_placement_group_id` instead of `capacity_reservation_group_id` as either one of them is allowed.
-`zone_balance` can only be set to `true` when zones are specified.
- Proximity placement group cannot span multiple availability zones. You must either remove the proximity placement group, or choose zero or one zone. Currently the module is using `proximity_placement_group_id` so the `zone_balance` is false.
- To enable the `automatic instance repair`, this Virtual Machine Scale Set must have a valid `health_probe_id` or an Application Health Extension.
- When Custom Data has been configured, it's not possible to remove it without tainting the Virtual Machine Scale Set, due to a limitation of the Azure API.
- We can create `Data_disk` in the Managed Disk module but cannot attach to the VMSS modules from Terraform hence, we have included the `data_disk` block to support multiple creation of data disks while deploying VMSS.
- While deploying the module with data_disk "name" parameter as per Terraform registry, getting error `dataDisk.name is not allowed` in Apply stage, hence, we have removed the "name" argument from the Data_disk block and a case has already been registered on [github](https://github.com/hashicorp/terraform-provider-azurerm/issues/23275).
- `terminate_notification` has been deprecated in favour of the `termination_notification` property and will be removed in version 4.0 of the provider.
- We are not enabling `SPOT` for this module, hence, the arguments related to it have been excluded.
- We will not be creating a `Confidential VMSS`(Azure confidential VMs offer a new and enhanced disk encryption scheme. This scheme protects all critical partitions of the disk. It also binds disk encryption keys to the virtual machine's TPM and makes the protected disk content accessible only to the VM. These encryption keys can securely bypass Azure components, including the hypervisor and host operating system. To minimize the attack potential, a dedicated and separate cloud service also encrypts the disk during the initial creation of the VM.) hence, not including the parameters `secure_vm_disk_encryption_set_id`, `security_encryption_type`.`
- `disk_size_gb` - this must be equal to or larger than the size of the Image the VM Scale Set is based on. When creating a larger disk than exists in the image you'll need to repartition the disk to use the remaining space.
- When using `load_balancer_backend_address_pool_ids` and `load_balancer_inbound_nat_rules_ids`,  you'll also need to configure a Rule for the Load Balancer, and use a depends_on between this resource and the Load Balancer Rule.
- To use maintenance assignment, set `maintenance_assignment_required` variable to `true` and provide `maintenance_configuration_id` to the windows virtual machine scale set.
- For `OSImage` maintenance scope, set the following variables:
 `upgrade_mode = Automatic`
 `enable_automatic_updates = false`
 `enable_automatic_os_upgrade = true`
 `health_probe_id = health probe id of the load balancer`
 `load_balancer_backend_address_pool_ids = backend address pool id of the load balancer`
- The key `HealthExtension` is hardcoded and must be used in the `var.extension` map for configuring the health extension. Other extensions can use custom keys.
- If you wish to update the repair action of an existing `automatic_instance_repair` policy, you must first disable the `automatic_instance_repair` policy before you can re-enable the `automatic_instance_repair` policy with the new repair action defined.
- To enable Ultra SSD data disk support on the Virtual Machine Scale Set, set `ultra_ssd_enabled` to `true`. Note that Ultra SSD requires the VMSS to be deployed in a supported region and availability zone, and the VM size must support Ultra Disks.
- To verify the deployed User Data on the Virtual Machine Scale Set, we can follow the below steps:
    - Login to the individual instance using RDP with the `administrator username` and `password from Key Vault`,
    - Open PowerShell and query the Azure Instance Metadata Service (IMDS) to retrieve the user data:
      ````powershell
      $userData = Invoke-RestMethod `
        -Uri "http://169.254.169.254/metadata/instance/compute/userData?api-version=2021-12-13&format=text" `
        -Headers @{Metadata="true"}
      ```
    - Decode the Base64 response to verify the user data content:
      ```powershell
      [System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String($userData))
      ```

#### Security Considerations

- For testing with the VMSS password, we can follow the below steps:
  1. Use `random_password` resource to generate the administrator password,
  2. Use the same generated password to deploy the Windows Virtual Machine Scale Set,
  3. Store the generated password as a secret in the Key Vault, named after the Virtal Machine Scale Set name,
  4. Additional role(`Key Vault Secrets User`) is required  on the Key Vault to manage the password as Key Vault secret.
- `Microsoft.Compute/EncryptionAtHost` feature should be enabled for the subscription to use Encryption at host level.
- The Disk Encryption Set must have the Reader Role Assignment scoped on the Key Vault.

#### Additional Information

- The `Plan` block accepts specific Marketplace images from [Image Marketplace Portal](https://azuremarketplace.microsoft.com/en-us/marketplace/apps?filters=virtual-machine-images) which has the arguments referencing to categories of the images similar to `source_image_reference`, example:
  ```tf
    plan = {
       name      = "2019-datacenter-gensecond"
       product   = "WindowsServer"
       publisher = "MicrosoftWindowsServer"
   }
  ```
   However, if you are using this block, it will need an acceptance of the legal terms of the Image on Subscription. To do it, please refer the [link](https://learn.microsoft.com/en-us/cli/azure/vm/image/terms?view=azure-cli-latest). Hence, we have kept as null for now and creating VMSS using `source_image_reference` block.
- Refer the [documentation](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-orchestration-modes) for valid values of parameters such as `platform_fault_domain_count`.
- Currently, there is no option to disable public access from the OS Disk Networking in Terraform. [Active Issue on github](https://github.com/Azure/azure-rest-api-specs/issues/21325).
