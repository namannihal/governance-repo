# Front Door Rule module

## Overview

This terraform module creates an Azure Front Door rule.

## Prerequisites

- Azure CDN Front Door Profile needs to be created prior to this module.
- Azure CDN Front Door Origin group needs to be created prior to this module.
- Azure CDN Front Door Origin needs to be created prior to this module.
- Azure CDN Front Door Ruleset needs to be created prior to this module.

## Guidance

#### Usage

- This module creates Azure Front Door Rule in Azure.
- The Rules resource must include a depends_on meta-argument which references the azurerm_cdn_frontdoor_origin and the azurerm_cdn_frontdoor_origin_group.
- If the Front Door Rule has `order` value of `0` they do not require any conditions and the actions will always be applied.
- `actions` : You may include up to 5 separate `actions` in the actions block
- `route_configuration_override_action` : In the v3.x of the provider the cache_duration, cache_behavior and query_string_caching_behavior will have default values. You can use Terraform's ignore_changes functionality to ignore these default values. In v4.0 of the provider the cache_duration, cache_behavior and query_string_caching_behavior will NOT have default values and will need to be explicitly set in the configuration file.
- If the cdn_frontdoor_origin_group_id is not defined you cannot set the `forwarding_protocol`.
- `query_string_parameters` is a required field when the `query_string_caching_behavior` is set to `IncludeSpecifiedQueryStrings` or `IgnoreSpecifiedQueryStrings`.
- Content won't be compressed on Azure Front Door when requested content is smaller than `1 byte` or larger than `1 MB`.
- `request_header_action` and `response_header_action` :
  - `Append` causes the specified header to be added to the request with the specified value. If the header is already present, the value is appended to the existing header value using string concatenation. No delimiters are added. `Overwrite` causes specified header to be added to the request with the specified value. If the header is already present, the specified value overwrites the existing value. `Delete` causes the header to be deleted from the request.
  - `value` is required if the `header_action` is set to `Append` or `Overwrite`.
- `conditions`: You may include up to 10 separate conditions in the conditions block.
  - The `ssl_protocol_condition` identifies requests based on the SSL protocol of an established TLS connection.
  - The `host_name_condition` identifies requests based on the specified hostname in the request from client.
  - The `server_port_condition` identifies requests based on which port of the Front Door server accepted the request on.
  - The `client_port_condition` identifies requests based on the port of the client which made the request.
  - `socket_address_condition`
    - identifies requests based on the IP address of the direct connection to the Front Door Profiles edge. If the client used an HTTP proxy or a load balancer to send the request, the value of Socket address is the IP address of the proxy or load balancer.
    - Remote Address represents the original client IP that is either from the network connection or typically the X-Forwarded-For request header if the user is behind a proxy.
    - If the value of the `operator` field is set to `IpMatch` then the match_values field is also required.
    - See the Specifying IP Address Ranges section below on how to correctly define the match_values field.
  - `remote_address_condition`
    - Remote Address represents the original client IP that is either from the network connection or typically the `X-Forwarded-For` request header if the user is behind a proxy.
    - See the Specifying IP Address Ranges section below on how to correctly define the match_values field.
  - The `request_method_condition` identifies requests that use the specified HTTP request method.
  - Use the `query_string_condition` to identify requests that contain a specific query string.
  - Use the `post_args_condition` to identify requests based on the arguments provided within a `POST` request's body. A single match condition matches a single argument from the `POST` request's body.
  - The `request_uri_condition` identifies requests that match the specified URL. The entire URL is evaluated, including the protocol and query string, but not the fragment. When you use this rule condition, be sure to include the protocol(e.g. For example, use `https://www.contoso.com` instead of just `www.contoso.com`).
  - The `request_header_condition` identifies requests that include a specific header in the request. You can use this match condition to check if a header exists whatever its value, or to check if the header matches a specified value.
  - `request_body_condition`:
    - Identifies requests based on specific text that appears in the body of the request.
    - If a request body exceeds `64 KB` in size, only the first `64 KB` will be considered for the request body match condition
  - The `request_scheme_condition` identifies requests that use the specified protocol.
  - The `url_path_condition` identifies requests that include the specified path in the request URL. The path is the part of the URL after the hostname and a slash(e.g. in the URL https://www.contoso.com/files/secure/file1.pdf, the path is files/secure/file1.pdf).
  - The `url_file_extension_condition` identifies requests that include the specified file extension in the file name in the request URL. Don't include a leading period(e.g. use html instead of .html).
  - The `url_filename_condition` identifies requests that include the specified file name in the request URL.
  - `http_version_condition`:
    - Use the HTTP version match condition to identify requests that have been made by using a specific version of the HTTP protocol.
  - Use the `cookies_condition` to identify requests that have include a specific cookie.
  - Use the `is_device_condition` to identify requests that have been made from a mobile or desktop device
