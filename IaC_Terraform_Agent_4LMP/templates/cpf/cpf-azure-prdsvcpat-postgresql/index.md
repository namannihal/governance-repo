# PostgreSQL Flexible server and Database Service Pattern

[[_TOC_]]

This readme provides an overview of an service pattern for PostgreSQL Flexible server. The solution proposed below provides an easy predefined template built on top of LSEG approved Cloud Products (with identified common configurations) and the service pattern intended to help application teams with rapid deployments of infrastructure.

Here are some of the key advantages the proposed solution offers:

* **Rapid Deployment:** Service patterns are pre-defined templates that can be easily reused which accelerates the deployment process by eliminating the need to write configurations from scratch for each deployment, saving time and effort.
* **Standardization and Consistency:** Service patterns provide standardized templates and best practices for deploying specific  infrastructure that promotes consistent configurations. This ensures consistency across deployments, reducing the likelihood of configuration drifts/errors and making it easier to maintain and scale infrastructure.
* **Documentation:** Service pattern comes with built-in documentation that explain the purpose and usage of various components.
* **Security and Compliance:** Service pattern built on top of approved Cloud Products incorporate security best practices and compliance requirements, ensuring that infrastructure is deployed with security in mind from the outset. This reduces the likelihood of security vulnerabilities.
* **Reuse, Sharing and customization:** Teams can share and reuse patterns across projects and organizations. Patterns can be adapted, and customized over time as infrastructure/business requirements change.
* **Version Control:** Patterns can be version-controlled, allowing teams to track changes, roll back to previous configurations if issues arise, and collaborate more effectively through version control systems.

### Provisioned Azure services through IaC

* Azure PostgreSQL (Flexible) Server.
* Azure PostgreSQL Database.
* Azure Keyvault with Private Endpoint (Optional).
* Azure Keyvault in Secondary region - for Geo redundancy with private endpoint (Optional).
* Subnet.
* Network Security group.
* Route Table (Optional).
* PostgreSQL Private DNS Zone.
* User managed identity.
* User managed identity - for Geo redundancy (Optional).

### Identity management

* For connecting to Azure PostgreSQL, Microsoft Entra is the LSEG approved mechanism. Pattern supports the local authentication, but that requires an exception and the Azure policy exemption. In case, local autentication is required then Azure policy - `Custom-EntraIDAuthOnlyMustBeUsed-1.0.0` needs to be exempted before deployment.
* SPN used for deployment of pattern would get admin permission to the PostgreSQL Server automatically.
* Granting admin access to the additional user/SPN is provided as an optional component via the Microsoft Entra group.

### Secret management

 Azure Key Vault (AKV) is offered as an optional component, and it serves as the repository for the Customer Managed Key (CMK) needed to enabled encryption on the PostgreSQL server. AKV is utilized for two primary purposes.

* Storing the CMK Key.
* Managing the local administrator password for PostgreSQL, constituting an exception process for the policy.

### Networking

* The pattern provides flexibility to choose if the Azure PostgreSQL (Flexible) Server needs to be deployed with VNET integration or Private end point. By default the configuration for VNET inetgration is implemented.
* Azure PostgreSQL (Flexible) Server VNET integration requires a Subnet with delegation to PostgreSQL service. Subnet creation would be provided as an optional component. Which would be deployed in LSEG complaint non routable VNET (scaffolded in application landing zone). It also gets deployed with the required delegation to psql ("Microsoft.DBforPostgreSQL/flexibleServers") and service endpoint for Microsoft.Storage.
* Azure PostgreSQL (Flexible) Server requires a private DNS Zone for name resolution, Private DNS Zone creation is offered as an optional component. DNS Zone is linked to the both routable and Non-routable Virtual networks.

### Availability

* Service Pattern supports geo redundancy and zone replicas.

### Other

* Using the service pattern it is possible create desired number of Postgres databases in the PostgreSQL server.

## PostgreSQL Backup Enhancements

* This module now supports long-term backup for PostgreSQL databases via Azure Backup Vault.

### Pattern Usage

#### Prerequisites

1. Routabe and Non-routable Virtual networks
2. Peering between Routabe and Non-routable Virtual networks

#### Build and Test

1. Call the module whichever is needs to be deployed. As the example given below,

  ```tf
  module "azure-prdsvcpat-terraform-postgresql" {
    source           = "git::https://gitlab.dx1.lseg.com/app/app-51310/azure/prdsvcpat/terraform/azure-prdsvcpat-terraform-postgresql-v1?ref=<pattern-version-tag>"
    org_id           = var.org_id
    app_id           = var.app_id
    location         = var.location
    environment      = var.environment
    context          = local.context
    instance         = var.instance
    tags             = var.tags
    secondary_region = var.secondary_region

    #### Platform and Application Dependencies ####
    resource_group_name                  = var.resource_group_name
    platform_rtbl_vnet_id                = var.platform_rtbl_vnet_id
    shared_nrtbl_vnet_id                 = var.shared_nrtbl_vnet_id
    resource_group_name_secondary_region = var.resource_group_name_secondary_region
    firewall_private_ip_address          = (var.azure_firewall_id != null && var.vnet_integration.delegated_subnet_id == null) ? data.azurerm_firewall.afw[0].ip_configuration[0].private_ip_address : null

    #### Postgresql Service Pattern Variables
    privateendpoint_subnet_id = var.privateendpoint_subnet_id
    vnet_integration = {
      delegated_subnet_id = var.vnet_integration.delegated_subnet_id
      private_dns_zone_id = var.vnet_integration.private_dns_zone_id
    }
    key_vault_config = {
      context                         = var.key_vault_config.context
      instance                        = var.key_vault_config.instance
      instance_geo                    = var.key_vault_config.instance_geo
      deploy_kv_and_pe                = var.key_vault_config.deploy_kv_and_pe
      deploy_kv_geo_and_pe            = var.key_vault_config.deploy_kv_geo_and_pe
      enabled_for_deployment          = var.key_vault_config.enabled_for_deployment
      enabled_for_disk_encryption     = var.key_vault_config.enabled_for_disk_encryption
      enabled_for_template_deployment = var.key_vault_config.enabled_for_template_deployment
      network_acls                    = var.key_vault_config.network_acls
      private_endpoint                = var.key_vault_config.private_endpoint
      key_vault_id                    = var.key_vault_config.key_vault_id     # == null ? module.azure-prdsvc-terraform-keyvault.id : var.key_vault_config.key_vault_id
      key_vault_geo_id                = var.key_vault_config.key_vault_geo_id # == null ? module.azure-prdsvc-terraform-keyvault.id : var.key_vault_config.key_vault_geo_id
      kv_secret_expiration_in_months  = var.key_vault_config.kv_secret_expiration_in_months
      sku_name                        = var.key_vault_config.sku_name
      secret_name_psql_admin_password = var.key_vault_config.secret_name_psql_admin_password
      kv_admin_role_app_spn_object_id = data.azuread_client_config.current.object_id
    }
    network_config                    = var.network_config
    backup_retention_days             = var.backup_retention_days
    create_mode                       = var.create_mode
    server_version                    = var.server_version
    sku_name                          = var.sku_name
    storage_mb                        = var.storage_mb
    zone                              = var.zone
    geo_redundant_backup_enabled      = var.geo_redundant_backup_enabled
    high_availability                 = var.high_availability
    identity_type                     = var.identity_type
    active_directory                  = var.active_directory
    password_auth_enabled             = var.password_auth_enabled
    admin_object_id                   = var.admin_object_id == null ? data.azuread_client_config.current.object_id : var.admin_object_id
    administrator_login               = var.administrator_login
    admin_principal_name              = var.admin_principal_name
    source_server_id                  = var.source_server_id
    source_server_location            = var.source_server_location
    auto_grow_enabled                 = var.auto_grow_enabled
    cmk_expiration_date               = var.cmk_expiration_date
    cmk_rotation_policy               = var.cmk_rotation_policy
    tenant_id                         = var.tenant_id == null ? data.azuread_client_config.current.tenant_id : var.tenant_id
    point_in_time_restore_time_in_utc = var.point_in_time_restore_time_in_utc # Required for `PointInTimeRestore` Create Mode
    configuration                     = var.configuration
    maintenance_window                = var.maintenance_window
    psql_db                           = var.psql_db

    depends_on = []
  }
  ```

1. Update the source with right tag version.
2. Check the terraform.tfvars file and update the values of org\_id, app\_id, location, context and instance.
3. If the plan is use to use the existing resouce available on azure then plase make an use of 'data block'
4. Update the values of variables in '.tfvars file'. In above example all `var.` varaibles are coming from the terraform.tfvars file in the .tests/deployTest folder.
5. **Note: The .tests/deployTest folder is for for deployment and unit test cases , Use only as reference and not as the exact implementation of the pattern.**
