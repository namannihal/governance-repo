# API Management Service module

## Overview

This terraform module creates a API Management Service and associated resources including Products, product policies, API's, APIM policy, API policies and subscriptions.

### Prerequisites

- There are set of ports needs to be allowed in NSG before we create the APIM using this Product

| Source / Destination Port(s)  | Direction | Transport protocol | Service tags Source / Destination | Purpose | VNet type | Required/Optional |
|---------|------------|---------------|-------------|-------------|---------------------|----------|
| * / 3443 | Inbound  | TCP  | ApiManagement / VirtualNetwork  | Management endpoint for Azure portal and PowerShell  | Internal | Required |
| * / 6390 | Inbound  | TCP  | AzureLoadBalancer / VirtualNetwork  |Azure Infrastructure Load Balancer  | Internal | Required |
| * / 443 | Outbound  | TCP  | VirtualNetwork / Storage  | Dependency on Azure Storage  | Internal | Required |
| * / 1433 | Outbound  | TCP  | VirtualNetwork / SQL  | Access to Azure SQL endpoints  | Internal | Required |
| * / 443 | Outbound  | TCP  | VirtualNetwork / AzureKeyVault  | Access to Azure Key Vault  | Internal | Required |

## Guidance

#### Usage

### AzureRM 4.x Upgrade Notes for API Management

**Impact analysis:** Medium

When migrating from `azurerm` 3.x to 4.x for API Management resources, users should be aware of the following major changes:

- The deprecated `policy` block within the `azurerm_api_management` resource has been removed.  
  - **Action required:** Replace any usage of the `policy` block with the standalone [`azurerm_api_management_policy`](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/resources/api_management_policy) resource.  
  - Pass your policies as a variable (e.g., `apim_policies`) to the module and use this variable to create `azurerm_api_management_policy` resources.
- In both the `hostname_configuration` block and the `azurerm_api_management_custom_domain` resource, the argument `key_vault_id` has been replaced with `key_vault_certificate_id`.  
  - **Action required:** Update your configuration to use `key_vault_certificate_id` instead of `key_vault_id` when referencing certificates from Azure Key Vault.
- In the `security` block, the following arguments have been renamed:
  - `enable_backend_ssl30` → `backend_ssl30_enabled`
  - `enable_backend_tls10` → `backend_tls10_enabled`
  - `enable_backend_tls11` → `backend_tls11_enabled`
  - `enable_frontend_ssl30` → `frontend_ssl30_enabled`
  - `enable_frontend_tls10` → `frontend_tls10_enabled`
  - `enable_frontend_tls11` → `frontend_tls11_enabled`
  - **Note:** There is no impact for the users as the variables for these arguments remain the same.

For more details, refer to the official [AzureRM 4.x Upgrade Guide](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/guides/4.0-upgrade-guide#azurerm_api_management).

For LSEG-specific guidance, see the [AzureRM 4.x Upgrade Wiki for API Management](https://gitlab.dx1.lseg.com/groups/app/app-51310/azure/prdsvc/terraform/-/wikis/Terraform-AzureRM-Provider-Upgrade:-Version-3.x-to-4.x/Api-Management).

- This module is designed to create APIM and all sub resources, to allow flexibilty to create multiple of these services each component is passed as variable to the module like below tfor products. Key of the map is the name of the component and value is the different argumanets for the components creation.

```
products = {
    "product1" = {
      display_name          = "product1"
      published             = true
      description           = "Update description"
      subscription_required = true
      approval_required     = true
      subscriptions_limit   = "1"
      terms                 = "Accept required terms"
    }
  }

```

- The current version is not capable to create APIs and subscriptions at the same time. So to create subscriptions
  1. APIs needs to be created using APIs variable.
  2. Then the API ID needs to be fetched using the Azure CLI or Azure API call resource [Azure API calls](https://learn.microsoft.com/en-us/rest/api/apimanagement/apis/get?view=rest-apimanagement-2024-05-01&tabs=HTTP#code-try-0)
  3. Then use the above value as API ID value for subscriptions creation in the next run.

```
  subscriptions = {
    "subscription1" = {
      display_name    = "Subscription test"
      user_id         = null
      api_id          = "/subscriptions/b92c1e38-1ee5-4e49-aed9-6061b3a78507/resourceGroups/a0a-51310-dev-rg-testing-uks-02/providers/Microsoft.ApiManagement/service/a1a-51310-dev-apim-dvapi-uks-190/apis/api1"
      product_id      = null
      primary_key     = null
      secondary_key   = null
      state           = null
      subscription_id = null
      allow_tracing   = null
    }
  }
```
- Azure Provider will attempt to Purge the API Management during deletion. This feature is forced using the `features` block within the provider.
- Azure API Management uses the Service Endpoint to the Subnet for establishing the communication to Azure SQL,Azure Storage,Azure EventHub, Azure Service Bus and Azure Keyvault.By enabling endpoints directly from the API Management subnet to these services, you can use the Microsoft Azure backbone network, providing optimal routing for service traffic.
- Azure APIM Management required the UDR in order to complete the successfull activation of the Product.This UDR should have the route with following configuration:
  - Destination Service Tags = APIManagement
  - Next Hope = Internet
- If you've deleted a public IP address and are trying to redeploy it with the same DNS name label, you may need to wait for a few hours for the DNS system to recognize that the label is available again. This waiting period allows Azure's systems to update and reflect the change in availability of the DNS name label. This varies and hence for predictability we have used random block for `domain_name_label`, might not fit for everyone's usecase.

```
resource "random_string" "random" {
  length  = 3
  special = false
  upper   = false
}

```
- AZAPI resource blocks have been added to enable diagnostics for API management. Currently, this version of module only supports `Application Insights` as the logger target. As tested, Terraform doesn't support enabling the diagnostics with `azuremonitor` as an `identifier`. A bug had also been registered on [github](https://github.com/hashicorp/terraform-provider-azurerm/issues/20358).

#### Security Considerations

- If the Vnet is using custom DNS Servers it should be able to forward the requests to Azure Provided DNS Server.
- As per policy requirement in greenfield, we need to enable SSL for the APIM resource deployed. Thus, ensure to set `security.enable_backend_ssl30 = true` and `security.enable_frontend_ssl30 = true`.

#### Additional Information

- Azure API Management is a hybrid, multicloud management platform for APIs across all environments. As a platform-as-a-service, API Management supports the complete API lifecycle.
- Azure API Management is made up of an API gateway, a management plane, and a developer portal. These components are Azure-hosted and fully managed by default.
- All requests from client applications first reach the API gateway, which then forwards them to respective backend services. The API gateway acts as a facade to the backend services, allowing API providers to abstract API implementations and evolve backend architecture without impacting API consumers.
- With the self-hosted gateway, customers can deploy the API gateway to the same environments where they host their APIs, to optimize API traffic and ensure compliance with local regulations and guidelines.
- API providers interact with the service through the management plane, which provides full access to the API Management service capabilities.
- APIs are the foundation of an API Management service instance. Each API represents a set of operations available to app developers. Each API contains a reference to the backend service that implements the API, and its operations map to backend operations.
- Products are how APIs are surfaced to developers. Products in API Management have one or more APIs, and can be open or protected. Protected products require a subscription key, while open products can be consumed freely.
- API Management service involve below key components: APIs, Products, Groups, Developers, Policies
- Premium SKU's are limited to a default maximum of 12 (i.e. Premium_12), this can, however, be increased via support request.
- Consumption SKU capacity should be 0 (e.g. Consumption_0) as this tier includes automatic scaling.
- Availability zones are only supported in the Premium tier.
- Custom public IPs are only supported on the Premium and Developer tiers when deployed in a virtual network.
- Either key_vault_id or certificate and certificate_password must be specified.
- If a User Assigned Managed identity is specified for ssl_keyvault_identity_client_id then this identity must be associated to the azurerm_api_management within an identity block.
- Setting key_vault_id requires the identity block to be specified, since this identity is used for to retrieve the Key Vault Certificate. Auto-updating the Certificate from the Key Vault requires the Secret version isn't specified.
- We are currently using the 2023-09-01-preview API version with Terraform as of 17-Dec-2024 for APIM resources loggers and diagnostics since latest version 2024-05-01 results in an error due to unsupported API version parameters.
