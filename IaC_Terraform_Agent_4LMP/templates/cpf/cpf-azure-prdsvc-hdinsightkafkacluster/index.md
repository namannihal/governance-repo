# HDInsight Kafka Cluster module


## Overview

- This terraform module creates a HDInsight Kafka Cluster and associated resources.
- Apache Kafka is an open-source distributed streaming platform that can be used to build real-time streaming data pipelines and applications. Kafka also provides message broker functionality similar to a message queue, where you can publish and subscribe to named data streams.
- The Apache Kafka API can only be accessed by resources inside the same virtual network.

## Prerequisites

- A `Virtual Network`, `Subnet`, `Azure SQL server` and `database` to be used by the Cluster in the same region.
- Each of your subscriptions has a per-region quota on the number of cores that HDInsight clusters can consume. Please refer for the [supported node configuration](https://learn.microsoft.com/en-us/azure/hdinsight/hdinsight-supported-node-configuration) to check on the same. If you'd like to increase the core quota in a region, please request [billing support](https://portal.azure.com/?#blade/Microsoft_Azure_Support/HelpAndSupportBlade).
- If you have firewall setting on HDInsight network, please kindly follow the following document for configuration to allow outbound access to HDI resource provider.
  - [Firewall_with_Application_rules](https://learn.microsoft.com/en-us/azure/hdinsight/hdinsight-restrict-outbound-traffic#configure-the-firewall-with-application-rules)
  - [Firewall_with_Network_rules](https://learn.microsoft.com/en-us/azure/hdinsight/hdinsight-restrict-outbound-traffic#configure-the-firewall-with-network-rules)
- SPN Roles:
  - Microsoft.Sql/servers/virtualNetworkRules/write to create VNET rules in an existing SQL Server.
  - Microsoft.Network/virtualNetworks/subnets/joinViaServiceEndpoint/action for HDInsights to access SQL Server.

## Guidance

#### Usage

- Please refer the documentation for [Azure HDInsight Versions](https://learn.microsoft.com/en-us/azure/hdinsight/hdinsight-component-versioning) to make sure you choose the correct `cluster_version` as well as the `kafka_component_version` which doesn't work if you mention the "patch" version. We have a [github_issue](https://github.com/MicrosoftDocs/azure-docs/issues/44155) on the same.
- One of the storage_account or storage_account_gen2 blocks must be marked as the default.
- Either a password or one or more ssh_keys must be specified - but not both.
- The `Ambari`, `Hive`, and `Oozie` metastores has the following requirements:
    1. The name of the database cannot contain `hyphens` or `spaces`.
    2. You must have an `existing` Azure SQL DB server and database.
    3. The database that you provide for metastores must be `empty`. There should be no tables in the default dbo schema.
    4. The `user` used to connect to the database should have `SELECT`, `CREATE TABLE`, `INSERT`, `UPDATE`, `DELETE`, `ALTER ON SCHEMA` and `REFERENCES ON SCHEMA` permissions on the database.
  For more details, kindly follow [this](https://learn.microsoft.com/en-us/azure/hdinsight/hdinsight-custom-ambari-db) guide to create a compatible resource. The `password` for these databases cannot include the characters `-{}'[]\"\\\\`.
- "System Assigned Identity" is not supported.
- Gateway credentials must be different from the one used for the `head_node`, `worker_node` and `zookeeper_node` roles.
- The maximum number of tags allowed is `15`.
- `administrator_login` for MSSQL and `username` of `Hive`, `Ambari`, and `Oozie` should be same.

#### Security Considerations

- To enabled the private link the connection_direction must be set to Outbound.
- The VNET and the Cluster must be in the same region and subscription.
- You cannot add an existing HDInsight cluster into a virtual network.
- When configuring Virtual Network and Firewall rules in SQL Server, it’s essential to **note** that complete disabling of public network access is not possible. The `networking` of SQL Server should be `Selected Networks`.
- When privateLink is set as enabled, internal standard load balancers (SLBs) are created, and an Azure Private Link service is provisioned for each SLB. The Private Link service is what allows you to access the HDInsight cluster from private endpoints. Thus **do not** modify this load balancer.
- Starting on June 30, 2020, Azure HDInsight will enforce TLS 1.2 or later versions for all HTTPS connections. For more information, see Azure HDInsight TLS 1.2 Enforcement. Hence, the value of `tls_min_version` has been harcoded to 1.2.
