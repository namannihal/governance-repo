# Azure Application Gateway module


## Overview

This terraform module creates an Application gateway and associated resources. Azure Application Gateway is a web traffic load balancer that enables you to manage traffic to your web applications. Traditional load balancers operate at the transport layer (OSI layer 4 - TCP and UDP) and route traffic based on source IP address and port, to a destination IP address and port.
Web Application Firewall (WAF) is an extra feature that can be added to App Gateway to provide protection from common web-based attacks, such as SQL injections or cross-site scripting. It is recommended to deploy App Gateway with WAF. App Gateway and WAF are two Separate LSEG Cloud Products, each residing in its own separate GitLab repository with self-contained documentation, terraform modules, and deployment pipeline.
For more information please refer to How an application gateway works.

## Prerequisites

- Existing `resource_group` and `virtual_network`
- Single `user_assign_identity`, `public_ip`, `rbac`, `time_sleep` function, `key_vault_certificate`, `key_vault`, `private_endpoint` and `web_application_firewall_policy`.
- 2 `network_security_group` and `subnet`

## Guidance

## Features

- Supports both `Standard_v2` and `WAF_v2` SKUs for Azure Application Gateway.
- Automatically assigns `firewall_policy_id` only when using `WAF_v2` SKU.
- Compatible with environments that do not require Web Application Firewall.

- The `min_protocol_version` property in the `ssl_profile` variable defaults to `TLSv1_2`

#### Others

- Application gateway frontend IP can be public on private.
- Whenever Application gateway backend pools are created then the module will associate them with network interface.
- Please make a note same frontend port cannot be used while creates Basic listener and if you want to create Multisite listener please call variable `listener_type = MultiSite`.
- Frontend IP name should be same for listeners, it could be public or private frontend IP.
- Host name should be specified or pick host name from backend address, whenever you are selecting pick host name from backend address it will pick from backend server.
- Identity that should be configured on this Application Gateway would be UserAssigned.
- Following settings are added to align with policy - "Web Application Firewall (WAF) should be enabled for Application Gateway".
- Default value of variable  "force_firewall_policy_association" is set as true.
- Automatically assigns `firewall_policy_id` only when using `WAF_v2` SKU.
- When using `WAF_v2`, provide a valid `firewall_policy_id` to enable WAF features.
- Variable firewall_policy_id is required.
- A "time_sleep" resource block is added while testing the module through validation pipeline, to allow key vault complete the private endpoint configuration so that while creating certificate it can access the key vault over the private Ip.
- `Software-validated` certificates are supported by Application gateway and `Hardware Security Module (HSM)-validated` certificates are not supported. For Software-Validated Certificates, key-type supported are RSA, RSA-HSM , EC ,EC-HSM and oct. We can store certificates in key vault and upload it to app gateway.
- If value of `match` within `probe` is not provided or set to null, Azure sets the allowed `status_codes` variable within `match` as `["200-399"]` by default. Hence, `status_codes` within `match` variable is set to `["200-399"]` by default in variables.tf file to avoid redeployment changes when match is set to null or not provided by developer. [Azure documentation - Custom health probe](https://learn.microsoft.com/en-us/azure/application-gateway/application-gateway-probe-overview#custom-health-probe-settings)

## Policy Considerations

- **Note** : Some Azure environments enforce a policy that requires all Application Gateways to have WAF enabled, regardless of whether they are public or internal.
- If you receive a policy error such as:-

  ```text
  RequestDisallowedByPolicy: Resource ... was disallowed by policy. Reasons: 'Resources are not compliant with the policy definition ... related to ControlID 'AGW-SC_010'.
  ```

- This is an Azure Policy enforcement and not a module limitation.
- If you must use `Standard_v2` without WAF, request an exemption or update to the policy from your cloud governance team.
- For most environments, use `WAF_v2` and provide a valid `firewall_policy_id`.

### Security Considerations

- Web application firewall module is utilized while testing the module through validation pipeline, to create a WAF and pass its id in application gateway module.
- TLS termination with Key Vault certificates is limited to the v2 SKUs.
- For TLS termination with Key Vault certificates to work properly existing user-assigned managed identity, which Application Gateway uses to retrieve certificates from Key Vault, should be defined via identity block. Additionally, access policies in the Key Vault to - allow the identity to be granted get access to the secret should be defined.
- The AllowApplicationGatewayPrivateLink feature must be registered on the subscription before enabling private link.
- In request_routing_rule the backend_address_pool_name, backend_http_settings_name, redirect_configuration_name, and - rewrite_rule_set_name are applicable only when rule_type is Basic.
- In request_routing_rule the priority is required when sku.0.tier is set to *_v2.
- In ssl_certificate block When specifying a file, use data = filebase64("path/to/file") to encode the contents of that file.
- In url_path_map block Both default_backend_address_pool_name and default_backend_http_settings_name or - default_redirect_configuration_name should be specified.
- In ssl_policy block disabled_protocols cannot be set when policy_name or policy_type are set.
- In ssl_policy block policy_type is Required when policy_name is set - cannot be set if disabled_protocols is set.
- In rewrite_rule_set block One or both of path and query_string must be specified. If one of these is not specified, it means the value will be empty. If you only want to rewrite path or query_string, use components.
- while creating `rewrite rule` there could be situation where `request` or `response` header value might need to be override.
  while overriding the `request` or `response` header, the `header_value` must not be `sensitive`, must use `nonsensitive` function.

### Additional Information

- Application Gateway is available under a Standard_v2 SKU. Web Application Firewall (WAF) is available under a WAF_v2 SKU.
Unsupported regions: The Standard_v2 and WAF_v2 SKU is not currently available in the following regions:

1. UK North
2. UK South2
3. China East
4. China North
5. US DOD East
6. US DOD Central

- Important Note: As per Microsoft public documentation, it is recommended not to have NSG and route table on application gateway subnet, to avoid nondeterministic behaviour and unknown backend pool member status issue. Refer to this [link](https://learn.microsoft.com/en-us/azure/application-gateway/application-gateway-faq#what-could-cause-backend-health-to-return-an-unknown-status) for more details.
