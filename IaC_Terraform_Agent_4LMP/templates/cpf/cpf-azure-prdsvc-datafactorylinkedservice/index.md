# Azure Datafactory Linked Service module


## Overview

This terraform module creates a Azure Datafactory Linked Service and associated resources.

## Prerequisites

- Resource Group, Virtual Network (both modules to be called if not existing, if allowed by the deployment permissions).
- Subnet to be used by the Key Vault Private endpoint.
- Network Security Group to be associated with the Subnet.
- Route Table to be associated with the Subnet.
- Key Vault for resource Customer Managed Key encryption.
- Private Endpoint to create a private connection to the Key Vault.
- User Assigned Identity leveraged for both identity and Customer Managed Key encryption.
- Datafactory is required to enable the linked services connection.

## Guidance

#### Usage

##### Azure Data Factory Linked Services

- This module covers the linked services for `keyvault`, `sql database`, `sqlmi`, `sftp`, `azure file storage`,`azure postgresql`,`azure Blob storage`, `sqlserver`, `Custom Linked Service` and `azure function` as well, users can optionally create each linked services based on the requirement.
- The provided value for `url` for function app linked service, `key` for function app linked service, `connection_string` for sql database linked service and `connection_string` for azure file storage linked service are dummy values for the testing purpose. Users can pass the correct values based on the requirement.
- If user want to store the `connection_string` and `keys` to keyvault and retrieve credentials from the keyvault in datafactory, there is already an existing `keyvault` linked service in place.
- In this module, we are passing the `connection_string` to Key Vault and retrieving it using the `key_vault_connection_string` argument. For this, an existing Key Vault linked service is required
