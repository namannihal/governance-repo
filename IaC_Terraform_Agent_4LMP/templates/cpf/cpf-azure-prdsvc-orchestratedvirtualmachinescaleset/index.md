# Virtual Machine Scale Set (Flexible Orchestration mode) module


## Overview

This terraform module creates a Virtual Machine Scale Set in Flexible Orchestration mode supporting both Linux and Windows along with associated resources .

## Prerequisites

- `Resource Group`, `Virtual Network`, and `Route Table` (all three modules to be called if not existing).
- `Subnet` to be used by the Private endpoint and the VM Network Interface IP Configs.
- `Network Security Group` to be associated with the Subnet.
- `Keyvault` module to create a secret.
- `Privateendpoint` module to create a private connection to the Keyvault.
- `Role assignment` module to assign "Key Vault Secrets User" role to the client on the created keyvault.
- `Keyvault Secret` module to store the Key or passwords.
- `User Assigned Identity` module to refernce the managed identity.
- `Loadbalancer` modules to list the backendpools.
- `encryptionset` modules to enabling the encryption to host.
- `time_sleep` resource block to wait for the secret to get created till private connection is registered in the Private DNS Zone and `tls_private_key` resource block to generate SSH key Pair for the Linux VMSS.

## Guidance

#### Usage

- The module can be used to create either `Linux` or `Windows` VMSS based on the `vmss_type` variable.
  - When `vmss_type` = `"linux"`, the module uses azurerm_orchestrated_virtual_machine_scale_set.
  - When `vmss_type` = `"linuxtrustedlaunch"`, the module uses azapi_resource to deploy a Linux VMSS with Trusted Launch security features using the latest API version.
  - `"linuxtrustedlaunch"` is only supported for new Linux VMSS deployments, not for upgrading existing VMSS instances this feature is still in preview.
  - When `vmss_type` = `"windows"`, the module uses azapi_resource to deploy a Windows VMSS using the latest API version.

- Virtual Machine Scale Set in Flexible Orchestration mode does not support the System Assigned Identity, hence the module is using User Assigned Identity.

- Virtual Machine Scale Set in Flexible Orchestration mode does not support Azure AD authentication, as the System Assigned Managed Identity is mandatory to enable Azure AD authentication using `AADLoginForWindows` extension.

- Refer the [documentation](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-orchestration-modes) for valid values of parameters such as `platform_fault_domain_count`.

- To test with the Password and the SSH Keys, we can follow the below steps implemented in the .tests\deployTest\main.tf file:
  - For Windows:
    - Use `random_password` to generate the administrator password,
    - Use the same generated password to deploy the Windows Virtual Machine Scale Set,
    - Store the generated password as a secret in the Key Vault, named after the Virtal Machine Scale Set name,
    - Additional role(`Key Vault Secrets User`) is required  on the Key Vault to manage the password as Key Vault secret.

  - For Linux:
    - Use the `tls_private_key` resource block to generate the SSH Keys,
    - Refer the use of `tls_private_key` resource block in getting the value of `admin ssh public_key`in Linux VMSS Module,
    - Store the private key as a secret (named after the Virtal Machine Scale Set name) in the Key Vault to be used by the user to login the Linux Virtual Machine,
    - Additional role(`Key Vault Secrets User`) is required on the Key Vault to manage the key as Key Vault secret.

- To verify the deployed User Data on the Virtual Machine Scale Set, we can follow the below steps:
  - For Linux:
    - Login to individual instance using `username` and `ssh from keyvault`. After logging into the VM you can find the `userdata` under `/var/lib/cloud/instances/user-data.txt`.
    - To verify the same use `sudo cat user-data.txt`
      ```curl
      cd /var/lib/cloud/instances
      sudo cat user-data.txt
      ```

  - For Windows:
    - Login to the individual instance using RDP with the `administrator username` and `password from Key Vault`,
    - Open PowerShell and query the Azure Instance Metadata Service (IMDS) to retrieve the user data:
      ```powershell
      $userData = Invoke-RestMethod `
        -Uri "http://169.254.169.254/metadata/instance/compute/userData?api-version=2021-12-13&format=text" `
        -Headers @{Metadata="true"}
      ```
    - Decode the Base64 response to verify the user data content:
      ```powershell
      [System.Text.Encoding]::UTF8.GetString([System.Convert]::FromBase64String($userData))
      ```
      
##### Known Issues

> **⚠️ Important: AzAPI Provider Version Compatibility**
>
> There is a known issue with the AzAPI provider that may cause "Missing Resource Identity After Update" errors. This is related to Terraform Core and AzAPI provider version compatibility:
>
> **Recommended Configuration:**
>
> - **Terraform Core:** Version > 1.12.0
> - **AzAPI Provider:** Version ≤ 2.7.0
>
> **Issue Details:**
>
> - Users running Terraform Core versions below 1.12 commonly encounter identity-related issues after resource updates
> - AzAPI provider version 2.8.0 (latest) has a known problem with this issue
> - The fix is expected in future AzAPI provider releases
> - Versions up to 2.7.0 work without issues when used with Terraform Core > 1.12.0
>
> **References:**
>
> - [Error: Missing Resource Identity After Update · Issue #1023](https://github.com/Azure/terraform-provider-azapi/issues/1023)
> - [Error: Missing Resource Identity After Update - resource group · Issue #1027](https://github.com/Azure/terraform-provider-azapi/issues/1027)

##### CPF Product Limitations

> **⚠️ Note: CPF Product Compatibility**
>
> **The CPF product currently supports either Linux or Windows virtual machine scale sets, but not both simultaneously within the same deployment. Multiple SKUs are supported within the same OS type. This limitation will be addressed in future module versions.**

#### Security Considerations

> **⚠️ Important: Extension Configuration Security Warning**
>
> **Extension configurations are marked as `nonsensitive()` to avoid Terraform iteration constraints.** This means:
>
> - **Sensitive values in extension `settings` or `protected_settings` will be visible** in `terraform plan` and `terraform apply` output
> - **Key Vault secret URLs and vault IDs in `protected_settings_from_key_vault` will be visible** in logs and console output
> - **Use extreme caution when including passwords, API keys, certificates, or other sensitive data** in extension configurations
- Currently, there is no option to disable public access from the OS Disk Networking in Terraform. [Active Issue on github](https://github.com/Azure/azure-rest-api-specs/issues/21325).
