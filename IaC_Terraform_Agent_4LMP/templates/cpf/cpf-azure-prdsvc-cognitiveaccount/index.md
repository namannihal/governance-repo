# Cognitive Account module

## Overview

- This terraform module creates a Cognitive Account with Kind `OpenAI`, `ContentSafety`, `TextTranslation`, `SpeechServices`, `ComputerVision`, `TextAnalytics`, `FormRecognizer` and its associated resources.

## Prerequisites

- A `Subnet` in already existing `virtual network`
- A `Key Vault` to enable Customer Managed Key Encryption
- Role Assignment to `SPN` for specific reasons like `Purging` Cognitve Account.
    <br>Step 1: In order to Purge Cognitive account, following permission `Microsoft.CognitiveServices/locations/resourceGroups/deletedAccounts/delete` needs to be assigned at Subscription level for your existing SPN
    <br><br>Step 2: We have the custom role `Custom-subscription-Resource-Constrained-Contributor-1.0.0` created in all Environment which has the following actions:<br>
    [Image: CustomRoleActions]
    <br><br>Step 3: Raise an `SRE ticket` to add your `SPN` to the `Custom-subscription-Resource-Constrained-Contributor-1.0.0` role in the respective environment
    <br><br>Step 4: Validate if your `SPN` has the `Custom-subscription-Resource-Constrained-Contributor-1.0.0` role assigned:<br>
    [Image: RoleAssignmentoverSPN]

## Guidance

#### Usage

###### AzureRM 3.x to 4.x Upgrade Notes for Cognitive Account

Product Impact -- Medium

Users in azurerm 3.x migrating to 4.x need to consider the following changes

  - Replaced deprecated `scale` block with `sku` block in `azurerm_cognitive_deployment` resource.
  - Renamed variable `deployment_scale` to `deployment_sku` to align with latest provider naming conventions.
  - Updated `sku` block to support new parameters.
  - Added the `spn_object_id` variable to allow explicit control of the service principal object ID used in Open AI role assignments.
  During migration, the following role assignments will be destroyed and recreated due to changes in provider internals and how principal IDs are resolved.

  - `azurerm_role_assignment.spn_contributor` (Cognitive Services OpenAI Contributor)
  - `azurerm_role_assignment.spn_quota` (Cognitive Services Usages Reader)

  To prevent this, set `spn_object_id` to `data.azurerm_client_config.current.object_id`. This avoids unnecessary recreation of `azurerm_role_assignment` resources during migration.

  - Wiki link for [AzureRM 4.x Upgrade](https://gitlab.dx1.lseg.com/groups/app/app-51310/azure/prdsvc/terraform/-/wikis/Terraform-AzureRM-Provider-Upgrade:-Version-3.x-to-4.x/Cognitive-Account) for details on the upgrade process.

  - For more details, refer to the official [AzureRM 4.x Upgrade Guide](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/guides/4.0-upgrade-guide)

###### Others

- Azure Provider will attempt to Purge the Cognitive Account during deletion. This feature is forced using the `features` block within the provider.
- SKU `DC0` is the commitment tier for Cognitive Services containers running in disconnected environments. You must obtain approval from Microsoft by submitting the [request form](https://aka.ms/csdisconnectedcontainers) first, before you can use this SKU.

- Use `key_vault_tags` variable to define additional Key Vault Key/Secret related tags in your product. Note that azure policies are enforcing a number N of tags for all products by default. Also note that Key Vault child resources support only 15 tags as the maximum limit. Therefore, please ensure the total count of tags enforced by policy and tags applied via variable does not exceed the limit. For example, if 10 tags are enforced via Azure policy, a maximum of 5 tags can be set via the `key_vault_tags` variable. Reference link - [Key tags](https://learn.microsoft.com/en-us/azure/key-vault/keys/about-keys-details#key-tags).

- Use the `tags` variable to define additional tags related to the product (core). Note that azure policies are enforcing a number N of tags for all products by default and that additional 3 tags are set on the main product via main terraform template.
If you are assigning additional tags (key-value pairs) via the `tags` variable, please ensure the total count does not exceed the limit supported by Azure resources. Reference link - [Azure Resources Tag Limitation](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/tag-support)

#### Security Considerations

- Since `outbound_network_access_restricted = true`, we need to provide a list of outbound URL's to `fqdns` property that the Azure AI Service resources are allowed to access and Azure AI Service resource can access Key Vault resources for CMK purpose.
- `Customer Managed Key` requires `identity_client_id` which is the Client ID of the User Assigned Identity that has access to the key. This property only needs to be specified when there're multiple identities attached to the Cognitive Account.
- The subscription must have `Microsoft.CognitiveServices/locations/resourceGroups/deletedAccounts/delete` permissions to purge resources, such as `Cognitive Services Contributor` or `Contributor`.
- Azure account must have a `Cognitive Services OpenAI Contributor` role assigned in order for you to agree to the responsible AI terms and create a resource like `Azure AI Vision`, `Azure AI Language`.
- User must Create first `Azure AI Language`, or `Azure AI Vision` resources from the Azure portal so that the terms and conditions can be reviewed and acknowledged. After that, user can create resources by using any deployment tool (for example, SDK, Azure CLI, or ARM template) under the same Azure subscription.
- `Customer Managed Key` is set to mandate for all `Kind`.
- This module has security controls implemented for `Kind = OpenAI, TextTranslation, FormRecognizer`.
- Azure OpenAI Services must use LSEG-approved OpenAI models. If a model is not currently allowed, a policy exemption for Control ID: AOAI-SC_020 must be requested with the Cyber team. See https://lsegroup.sharepoint.com/sites/LSEG-engineering/SitePages/Approved-Large-Language-Models.aspx for approved models. The models listed in the document are approved for general development and test use only.

#### Additional Information

- Azure AI services resource creation doesn't require any registration to avail the service since it is generally available in public domain.
- Check [Model Availability](https://learn.microsoft.com/en-us/azure/ai-services/openai/concepts/models#standard-deployment-model-availability) in a particular region before initiating deployment.
- Check on necessary [roles and permissions](https://learn.microsoft.com/en-us/azure/ai-services/openai/how-to/role-based-access-control) before Cognitive Deployment of Model.
- `Cognitive Services Contributor` role required to edit model and deployments and `Cognitive Services Usages Reader` role required for Accessing quota for model deployments.
- This module creates Cognitive Account and 7 other kinds and model, scale deployment.
- The Cognitive Account deployment of kind OpenAI can take up to 3 hrs. Make sure to increase Project Timeout for the pipeline in such cases.
- For futher understanding of Azure AI services, please refer this techinical blog - [Get Started with Azure AI Services | Open AI and Deployment Models](https://techcommunity.microsoft.com/t5/azure-infrastructure-blog/get-started-with-azure-ai-services-open-ai-and-deployment-models/ba-p/4138583)
