# Azure Container Apps (ACA) Solution pattern

# Introduction 
This technical document provides an overview of an automation solution for Azure Container Apps pattern. The solution proposed below provides an easy predefined template built on top of LSEG approved Cloud Products (with identified common configurations) intended to help application teams with rapid deployments of ACA infrastructure. This is not a single solution for all application requirements and the application teams are required to review the solution and decide whether to reuse the solution as such or make necessary changes/integrations while using it in their deployments. 
Here are some of the key advantages the proposed solution offers:

* **Rapid Deployment:** Solution patterns are pre-defined templates that can be easily reused which accelerates the deployment process by eliminating the need to write configurations from scratch for each deployment, saving time and effort.
* **Standardization and Consistency:** Solution patterns provide standardized templates and best practices for deploying specific types of ACA infrastructure that promotes consistent configurations. This ensures consistency across deployments, reducing the likelihood of configuration drifts/errors and making it easier to maintain and scale infrastructure.
* **Documentation:** Solution patterns comes with built-in documentation that explain the purpose and usage of various components. 
* **Security and Compliance:** Solution patterns built on top of approved Cloud Products incorporate security best practices and compliance requirements, ensuring that infrastructure is deployed with security in mind from the outset. This reduces the likelihood of security vulnerabilities.
* **Reuse, Sharing and customization:** Teams can share and reuse solution patterns across projects and organizations. Patterns can be adapted, and customized over time as infrastructure/business requirements change.
* **Version Control:** Solution patterns can be version-controlled, allowing teams to track changes, roll back to previous configurations if issues arise, and collaborate more effectively through version control systems.

## Prerequisites

- This Pattern assumes that you have an existing Azure Container Registry  which already has the required image in the registry, along with an existing Keyvault. This is to optimize the amount of resources being created in the pattern and re-use resources if possible.

- This pattern assumes that you have private endpoints in place for ACR and Keyvault already, or have communication established in some other way.

- This pattern promotes usage of Azure container registry to store the Images to be used by container apps, instead of using 3rd party image sources, to have greater control and security over the Images.



## Guidance

#### Usage
- This module deploys the Container App Pattern, which is basically deployment of Azure container apps where image is pulled from Azure Container Registry and Keyvault integration is done.
-  Container Apps basically supports two revisions such as Single mode and Multiple mode. In Single mode, a single revision is in operation at any given time. In Multiple mode, more than one revision can be active at a time and can be configured with load distribution via the traffic_weight block in the ingress configuration.
- In order to restrict public access and to limit the traffic to VNET, the key combination to be used is ingress with internal load balancer + custom Vnet + external to true.
- To limit traffic to container apps environment, the key combination to be used is ingress with internal load balancer + custom Vnet + external to false.
- Please be noted with regards to custom DNS server configuration. If your VNet uses a custom DNS server instead of the default Azure-provided DNS server, configure your DNS server to forward unresolved DNS queries to 168.63.129.16. Azure recursive resolvers uses this IP address to resolve requests. When configuring your NSG or firewall, don't block the 168.63.129.16 address, otherwise, your Container Apps environment won't function correctly. Do refer the article against DNS section.
https://learn.microsoft.com/en-us/azure/container-apps/networking?tabs=workload-profiles-env%2Cazure-cli
