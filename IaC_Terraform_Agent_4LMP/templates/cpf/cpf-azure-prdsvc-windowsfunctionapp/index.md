# Windows Function App module

## Overview

This terraform module creates a Windows Function App and associated resources.

## Prerequisites

A `resource group` has been created. The `virtual network` and `subnet` are already created. `key vault` needs to be created first, if not exists, to store sensitive information.

## Guidance

#### Usage

###### AzureRM 3.x to 4.x Upgrade Notes for Windows Function App

Product Impact -- Low

Users in azurerm 3.x migrating to 4.x  need to perform the following changes
  - Introduced the new variable 'vnet_image_pull_enabled'.

  - Wiki link for [AzureRM 4.x Upgrade](https://gitlab.dx1.lseg.com/groups/app/app-51310/azure/prdsvc/terraform/-/wikis/Terraform-AzureRM-Provider-Upgrade:-Version-3.x-to-4.x/Windows-Function-App) for details on the upgrade process.

For more details, refer to the official [AzureRM 4.x Upgrade Guide](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/guides/4.0-upgrade-guide)

## Others
- When running in a Consumption or Premium Plan, `always_on feature` in `site_config` should be turned off. Please turn it off before upgrading the service plan from standard to premium.
- `backend_storage_key_vault_secret_id` cannot be used with `backend_storage_account_name`.
- For all the values of `client_secret_setting_name` and `consumer_secret_setting_name`, a setting with this name must exist in app\_settings to function correctly.
- For application insight related settings, please use `application_insights_connection_string` and `application_insights_key`, terraform will assign the value to the key `APPINSIGHTS_INSTRUMENTATIONKEY` and `APPLICATIONINSIGHTS_CONNECTION_STRING` in app setting.
- For storage related settings, please use related properties that are available such as `storage_account_access_key`, terraform will assign the value to keys such as `WEBSITE_CONTENTAZUREFILECONNECTIONSTRING`, `AzureWebJobsStorage` in app\_setting.
- For health check related settings, please use `health_check_eviction_time_in_min`, terraform will assign the value to the key `WEBSITE_HEALTHCHECK_MAXPINGFAILURES` in app setting.
- For runtime related settings, please use `node_version` in site\_config to set the node version and use `functions_extension_version` to set the function runtime version, terraform will assign the values to the key `WEBSITE_NODE_DEFAULT_VERSION` and `FUNCTIONS_EXTENSION_VERSION` in app setting.
- Deployment Slots Support: The number of available deployment slots for Windows Function Apps depends on the hosting plan:
  - Consumption Plan: 2 slots
  - Flex Consumption Plan: Deployment slots are not currently supported
  - Premium Plan: 3 slots
  - Dedicated (App Service) Plan: 1-20 slots
- Slot Swap with Network-Restricted Storage: When performing a slot swap on a function app running on a Premium plan, the swap can fail when the dedicated storage account used by the app is network restricted. This failure is caused by a legacy application logging feature, which both Functions and App Service share. Set `WEBSITE_OVERRIDE_STICKY_DIAGNOSTICS_SETTINGS = "0"` in app settings to override that legacy logging feature and allow the swap to occur.
