# MYSQL Flexible server and Database Service Pattern

[[_TOC_]]

This readme provides an overview of an service pattern for MYSQL Flexible server. The solution proposed below provides an easy predefined template built on top of LSEG approved Cloud Products (with identified common configurations) and the service pattern intended to help application teams with rapid deployments of infrastructure.

Here are some of the key advantages the proposed solution offers:

* **Rapid Deployment:** Service patterns are pre-defined templates that can be easily reused which accelerates the deployment process by eliminating the need to write configurations from scratch for each deployment, saving time and effort.
* **Standardization and Consistency:** Service patterns provide standardized templates and best practices for deploying specific  infrastructure that promotes consistent configurations. This ensures consistency across deployments, reducing the likelihood of configuration drifts/errors and making it easier to maintain and scale infrastructure.
* **Documentation:** Service pattern comes with built-in documentation that explain the purpose and usage of various components.
* **Security and Compliance:** Service pattern built on top of approved Cloud Products incorporate security best practices and compliance requirements, ensuring that infrastructure is deployed with security in mind from the outset. This reduces the likelihood of security vulnerabilities.
* **Reuse, Sharing and customization:** Teams can share and reuse patterns across projects and organizations. Patterns can be adapted, and customized over time as infrastructure/business requirements change.
* **Version Control:** Patterns can be version-controlled, allowing teams to track changes, roll back to previous configurations if issues arise, and collaborate more effectively through version control systems.

### Provisioned Azure services through IaC

* Azure MYSQL (Flexible) Server.
* Azure MYSQL Database.
* Azure Keyvault with Private Endpoint (Optional).
* Azure Keyvault in Secondary region - for Geo redundancy with private endpoint (Optional).
* Subnet.
* Azure Key Vault key
* Azure Key Vault secret
* Network Security group.
* Route Table (Optional).
* MYSQL Private DNS Zone.
* User managed identity.
* User managed identity - for Geo redundancy (Optional).

### Identity management

* For connecting to Azure MYSQL, Pattern does not support "only Entra authentication". Thus, both MySQL and Entra authentication is provided using administrator_login and administrator_password for MySQL authentication and azurerm_mysql_flexible_server_active_directory_administrator resource block to assign Entra admin.
* SPN used for deployment of pattern would get admin permission to the MYSQL Server automatically.
* Granting admin access to the additional user/SPN is provided as an optional component via the Microsoft Entra group.

### Secret management

 Azure Key Vault (AKV) is offered as an optional component, and it serves as the repository for the Customer Managed Key (CMK) needed to enabled encryption on the MYSQL server. AKV is utilized for two primary purposes.

* Storing the CMK Key.
* Managing the local administrator password for MYSQL, constituting an exception process for the policy.

### Networking

* Azure MYSQL (Flexible) Server VNET integration requires a Subnet with delegation to MYSQL service. Subnet creation would be provided as an optional component. Which would be deployed in LSEG complaint non routable VNET (scaffolded in application landing zone). It also gets deployed with the required delegation to fs ("Microsoft.DBforMySQL/flexibleServers") and service endpoint for Microsoft.Storage.
* The vnet integration feature is optional now, since the current version supports private endpoint. End user can either choose vnet integration/ private endpoint for the Flexible Server
* If **var.network_config.use_vnet_integration**  set as **true** then vnet integration will be enabled. If it is **false** then Private endpoint will be created. Default value is **true**.
* Azure MYSQL (Flexible) Server requires a private DNS Zone for name resolution, Private DNS Zone creation is offered as an optional component. DNS Zone is linked to the both routable and Non-routable Virtual networks.

### Availability

* Service Pattern supports geo redundancy and zone replicas.

### Other

* Using the service pattern it is possible to create desired number of Mysql databases in the MYSQL server.

### Pattern Usage

#### Prerequisites

1. Routable and Non-routable Virtual networks
2. Peering between Routable and Non-routable Virtual networks

#### Build and Test

1. Call the module whichever is needs to be deployed. As the example given below,
