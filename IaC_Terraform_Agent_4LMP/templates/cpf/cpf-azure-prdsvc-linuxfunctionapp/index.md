# Azure Linux & Flex Consumption Function App Terraform Module


## Overview

This module enables deployment of Azure Linux Function Apps and Flex Consumption Function Apps (FC1 SKU) using Terraform. It supports robust configuration, conditional deployment, and feature parity between Linux and Flex Function Apps. The module is designed for enterprise use, with support for managed identities, authentication, client certificates, connection strings, sticky settings, deployment slots, traffic distribution, and slot swaps.

## Prerequisites

A `resource group` has been created. The `virtual network` and `subnet` are already created. `key vault` needs to be created first, if not exists, to store sensitive information.

## Guidance

#### Usage

###### How to Enable Flex Consumption (FC1) via Module
To deploy a Flex Consumption Function App, set the variable `flex_enabled = true` and provide a valid `flex_consumption_config` object. When `flex_enabled` is false (default), the module deploys a standard Linux Function App. If `flex_enabled = true` it can only deploy the `azurerm_function_app_flex_consumption`. Both `azurerm_linux_function_app` and `azurerm_function_app_flex_consumption` cant be deployed together as both of the resources deploy the linux function app with different configurations.  

###### Example
```hcl
module "function_app" {
  source        = "...path to module..."
  flex_enabled  = true
  flex_consumption_config = {
    storage_container_type      = "blobContainer"
    storage_container_endpoint  = "https://..."
    storage_authentication_type = "SystemAssignedIdentity" # or "UserAssignedIdentity"
    runtime_name                = "node"
    runtime_version             = "20"
    maximum_instance_count      = 100
    instance_memory_in_mb       = 2048
    always_ready = [
      { name = "default", instance_count = 1 }
    ]
  }
  # ...other required variables...
}
```

- For Linux Function App, set `flex_enabled = false` or omit it.
- For Flex, ensure all required fields of `flex_consumption_config` and common parameters of `linux_function_app` are provided.

Refer to the module documentation for all supported options and examples.

## Others
- For application insight related settings, please use application_insights_connection_string and application_insights_key, terraform will assign the value to the key APPINSIGHTS_INSTRUMENTATIONKEY and APPLICATIONINSIGHTS_CONNECTION_STRING in app setting.
- If you want to use the Docker block for the image, we've added the necessary code in the
.tests/deploytest/main.tf file. Please uncomment this code, change the registry value and comment out the `python_version` from the `application_stack` and run the pipeline.
- Linux Function app requires below settings to be enabled in storage account for accessing file share. The deployement might be successful, but the Function app may not be set up properly to run.
  - SMB Protocol Versions - `SMB 3.1.1`
  - SMB Channel Encryption - `AES-128-GCM`
  - Authentication Mechanisms - `NTLM v2`
- Deployment Slots Support: The number of available deployment slots depends on the hosting plan:
  - Consumption Plan: 2 slots
  - Flex Consumption Plan: Slots are not supported
  - Premium Plan: 3 slots
  - Dedicated (App Service) Plan: 1-20 slots
  - Container Apps: Uses Revisions instead of slots
- Slot Swap with Network-Restricted Storage: When performing a slot swap on a function app running on a Premium plan, the swap can fail when the dedicated storage account used by the app is network restricted. This failure is caused by a legacy application logging feature, which both Functions and App Service share. Set `WEBSITE_OVERRIDE_STICKY_DIAGNOSTICS_SETTINGS = "0"` in app settings to override that legacy logging feature and allow the swap to occur.

#### Security Considerations

- One of `backend_storage_account_access_key` or `backend_storage_uses_managed_identity` must be specified when using storage_account_name.
- `backend_storage_key_vault_secret_id` cannot be used with `backend_storage_account_name`.
- For runtime related settings, please use `node_version` in site_config to set the node version and use `functions_extension_version` to set the function runtime version, terraform will assign the values to the key `WEBSITE_NODE_DEFAULT_VERSION` and `FUNCTIONS_EXTENSION_VERSION` in app setting.
- For storage related settings, please use related properties that are available such as `backend_storage_account_access_key`, terraform will assign the value to keys such as `WEBSITE_CONTENTAZUREFILECONNECTIONSTRING`, `AzureWebJobsStorage` in app_setting. This applies for function app only.
- `shared_access_key_enabled` be set to `true` for the storage account being used to use the connection strings set via `AzureWebJobsStorage` and `WEBSITE_CONTENTAZUREFILECONNECTIONSTRING`
