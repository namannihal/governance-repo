# Versioning Convention

For versioning your projects, consider using Semantic Versioning (SemVer). SemVer is a versioning system that helps maintain backward compatibility while releasing new versions of your software. You can learn more about Semantic Versioning [here](https://semver.org/).

Semantic Versioning (SemVer) is a versioning system that helps maintain backward compatibility while releasing new versions of your software. The version number is structured as `MAJOR.MINOR.PATCH`, and it follows these guidelines:

1. `MAJOR` version: Increment when you make incompatible API changes or introduce significant new features.
2. `MINOR` version: Increment when you add backward-compatible features or enhancements.
3. `PATCH` version: Increment for backward-compatible bug fixes or minor improvements.

##### Examples of Semantic Versioning:

1. `MAJOR` version increment:
   ```
   2.0.0

   - Major rewrite with breaking changes to the API.
   ```
   
2. `MINOR` version increment:
   ```
   1.2.0

   - Added new features in a backward-compatible manner.
   ```
   
3. `PATCH` version increment:
   ```
   1.1.1

   - Bug fixes and minor improvements.
   ```

By following Semantic Versioning, you can communicate the impact of your software updates to users and consumers of your projects, helping them understand the nature of the changes and their compatibility with existing code.
